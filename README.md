## 实现的主要链路

一个Raft对象表示一个节点，多个节点通过官方模拟网络交换RPC。实现按三条链路组织：

- **选举：** 选举到期进入新任期、自投票并拉票；处理回复时先承认更高任期，再过滤旧轮回复，达到多数派后成为领导者。
- **复制与交付：** 领导者接受命令后按跟随者进度构造请求；接收者核对前缀并修复后缀，领导者根据有效回复确认多数派提交，各节点再按顺序交付已提交命令。
- **保存与恢复：** 任期、投票或日志变化后编码保存；创建节点时先恢复这三项状态，再启动后台协程。角色及复制进度不作为这份持久化数据恢复。

共享可变状态由节点互斥锁保护，网络等待和通道发送在锁外完成。复制回复与本机保留的原请求关联，成功进度只增不减，过时失败不能直接覆盖新进度。有副本、已提交、本机知道已提交、已交付是不同状态。

### 3C：保存与重启恢复（实际疑问）

**24. 持久化这里的Go语法和API怎么用？能给一个例子吗？**（2026-10-04 23:24）

按“创建字节容器 → 创建编码器 → 按固定顺序编码状态 → 取得字节 → 交给保存容器”理解。bytes.Buffer负责容纳字节，labgob.NewEncoder负责把Go值编码进去，Encode返回的error要检查；编码成功后才能调用Persister.Save。恢复时反过来解码，Decode要传变量地址才能填写结果，读写顺序必须一致。完整实现保存在私有代码中。

**25. 为什么既有e又有w？它们分别干什么？**（2026-10-04 23:28）

w是存放编码结果的字节容器，e是向w写入数据的编码器：可以类比“装东西的盒子”和“把对象转换成字节的工具”。创建e不会自动保存字段，Encode才执行编码；w.Bytes取得结果，Save才把它交给官方保存容器。恢复时的容器装着旧字节，解码器从里面按顺序读取。

**26. tmp为空就不恢复吗？readPersist是自己实现，ReadRaftState是官方提供的吗？**（2026-10-04 23:39）

是。官方ReadRaftState取出此前保存的字节，自己的readPersist负责解释这些字节并恢复字段。首次启动没有保存数据，readPersist直接返回，保留Make初始化的任期、未投票标记和日志哨兵；有旧数据则先完整解码到临时变量再赋给节点。空数据与损坏数据不同，当前实现遇到解码错误会中断，不能静默当成首次启动。恢复完成后才启动后台协程。

**27. 所有修改votedFor、currentTerm、log的地方都要持久化，对吗？**（2026-10-04 23:41）

对，这三项需要跨重启保留。检查发现更高任期、发起选举并投给自己、授予选票、Start追加日志和AppendEntries修复后缀等路径；每次逻辑修改完成后，在依赖它的答复或消息对外生效前保存。可以在同一临界区完成一组修改再统一保存，不必每个赋值单独保存；日志没有变化的空心跳也不必因为日志再次保存。role、计票和复制进度不属于这三项持久化状态。
